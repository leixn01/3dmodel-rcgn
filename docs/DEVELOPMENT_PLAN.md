# 当前进度与下一步

当前MCP 0.14.0，36个工具、29个功能skill。Windows + 用户已有Conda；原始STEP保持不变。流程不设置人工复核门槛，不确定信息在结论说明风险。

## 本轮完成：目标实例图与模板局部匹配

- cad_build_target_graph：重放链级清单和空间/轴线/配合/距离/局部面来源，生成保留全部实例对的目标图。连接来源里的轴线关系自动收集；独立关系文件可追加。保留来源哈希、单位、部分结果、冲突和范围外联系。
- cad_match_mechanism_templates：在选定参考库中枚举连通窗口（默认3节点），有预算地搜索目标实例对应。输出关节类型假设、连接证据、相对轴向检查、竞争解释和搜索缺口。分数是明确权重的排序值，不是正确率。
- 两个独立skill按文件交接；29个入口均逐层披露。参考模板、纯算法、文件边界、MCP、skill分别维护；不增加COM依赖，不需要人工填写对应关系来生成候选。
- 默认只用6个reference，2个heldout仍需明确评测入口才允许使用。无关节、无正向证据或预算不足时保留未知，不硬凑机构。

## 当前边界

目标一个节点仍代表一个叶零件实例，参考一个节点代表作者标注的刚体。因此本轮适合寻找局部结构线索，不能处理一个实际运动刚体由多零件组成的所有对应情况。关节类型由参考提供假设，几何轴不是已验证关节轴；没有把参考行程、限位或传动比复制到目标。

离线回归、生产MCP协议与参考派生控制已提供自动验收。参考派生控制给定连接/轴向再隐藏名称和类型，只验证搜索性质，不能声称独立识别精度。当前开发环境未连接用户SolidWorks，尚未取得升降机实机匹配文件。

## 下一步：多零件刚体候选与关节参数草案

1. 根据现有局部候选、原始约束/几何及模板的刚体结构生成多零件刚体分组假设；保留每个原始实例和来源，不凭近接触直接合并，不修改CAD。
2. 对每个竞争分组/关节假设，列出可提取的目标轴位置/方向、缺少的约束与局部运动检查；自动按需补采，不能得到的参数留空并说明风险。
3. 输出一条升降链的刚体—关节草案与替代解释，做成员守恒、重复归属、边界连接和几何一致性检查，再扩展到其他重复链。
4. 之后再开发运动求解、干涉、行程/耦合与拆卸路径验证。结构候选与已验证运动关系始终分开。

本机可按[0.14.0验收](MCP_ACCEPTANCE.md#0140目标实例图与模板局部匹配)使用已有真实链清单运行匹配；缺输入时Agent调用相应独立采集能力，继续可完成部分，不等待人工机械确认。
