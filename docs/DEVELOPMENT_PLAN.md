# 当前任务：Windows 实机验收

更新：2026-11-10。MCP 第一版代码已经实现；现在重点是在用户已安装 SolidWorks 的 Windows 电脑验证，不再从头搭建连接层。

## 验收顺序

1. 按 README 安装虚拟环境和依赖。记录 Windows、Python、OpenCode、SolidWorks 版本；只保留一个目标 SolidWorks 进程。
2. 运行 CLI 会话检查，确认读取到真实进程与版本。通过 OpenCode MCP 再执行同一检查；协议连接成功不能替代 COM 成功。
3. 手动打开或用 `sw_open_document` 导入测试 STEP。核对文档标题、路径、实际类型、配置和 dirty 状态；若导入为多实体零件，记录事实并检查本机导入方式。
4. 对装配执行 `sw_component_tree`，保存原始 JSON 到 `outputs/solidworks_inventory.json`。核对根模型及至少三个组件，包括重复实例和一个子装配层级；记录部分失败和统计口径。
5. 用新读取的 token 执行等轴测/缩放，核对视图；选择一个组件并核对高亮，再清空选择。
6. 需要验证重建时，对工作副本执行 `sw_rebuild`，核对实际结果及 dirty 状态；不自动保存原始模型。
7. 切换文档或配置后，用旧 token 测试拒绝操作；检查无文档、零件输入和未解析组件的反馈。不要人为制造不可恢复的 COM 卡死。
8. 将结果、版本和必要截图留在 `outputs/`，更新验证记录时明确哪些来自真实 COM、哪些只是单元测试。修复实机兼容问题后提交相关代码与说明。

## 当前交付

已有 8 个 MCP 工具、共用 CLI、单 STA 调度、参数校验、目标文档核对，以及开源 COM 兼容片段。测试模型已内置。具体功能和限制见 [工具契约](TOOL_CONTRACTS.md)。

当前环境未运行 SolidWorks 或 OpenCode 客户端；不能填写实机验收通过。上游声称支持的版本也不能直接作为本项目兼容承诺。

## 验收后

先增加组件变换和配合读取，再选一条升降链做运动关系分析。后续改变组件位姿、写入配合或保存副本时，分别定义工具与验证方式，不提供任意 API/脚本执行入口。完整方向保留在 [路线图](ROADMAP.md)。
