# 当前进度与下一步

当前MCP 0.23.0，46个工具、39个功能skill。Windows + 用户已有Conda；原始STEP保持不变。自动处理可完成部分，未知与风险写在结论，不设置人工复核。

## 当前流程

读取目标组件/配置/位姿与配合/几何 → 指定链和目标图 → 局部约束分析、条件刚体和关系草案 → 按具体缺口规划补采 → 前后保护及原始记录 → 兼容回填、索引和约束重算。模板可选，仅提供类比。

0.23将约束报告接入有界流程：缺配合引用面几何或LockRotation时，可安排一次增强根配合读取。基础与增强能力分开；已尝试的增强不自动重试。所有保护调用计入预算，与通用采集/选面共享4轮。完整无配合、已有增强、不支持的规则及多快照歧义保留停止原因。

回填继续使用独立工具：重建有效来源与check，再生成索引和沿用原公差的约束报告；新报告绑定历史，下一次规划自动继承。partial/failed但保护通过的记录也保存并计轮；保护失败不复用。不同快照不拼约束、feature_id不跨源匹配。

## 当前边界

局部候选支持显式lock、同心圆柱+锁定旋转、不同位置平行同心轴、同心轴+沿轴重合平面。局部规则支持不等于整机可运动，目标最终类型仍unknown、DOF仍null；新候选不会自动覆盖草案类型或确认分组。

STEP没有保留配合时，补采不会创造配合约束。名称、同轴外观、近接触或bench_vise swivel均不提供目标运动类型。距离/限位配合、斜向平面、非平行轴、复杂/多实体配合及子装配内部约束尚不求解。

## 下一步

1. 对完整且精确绑定的目标约束增加局部约束秩/剩余运动分析，分别记录数学自由度、适用假设、冲突与缺失约束；不直接当作实际可运动。
2. 用本机单条升降链文件核对“端座—导轨”等关系。无配合的STEP继续从几何形成多种解释，报告不能收敛的原因，不强制模板匹配。
3. 后续再处理跨组件回路与整机一致性，然后开展受控运动、干涉和拆卸路径。

验收入口：[0.23.0](MCP_ACCEPTANCE.md#0230约束缺口自动补采与重算)。skill按分析、规划、执行、回填和索引分别组织，入口只提供最小流程，细节按需读取。
