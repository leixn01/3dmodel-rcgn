# 当前进度与下一步

当前MCP 0.17.0，43个工具、36个功能skill。Windows + 用户已有Conda；原始STEP保持不变。不设置人工复核，未确定信息在结论说明风险。

## 本轮完成：一轮有界补采闭环

- 独立执行工具sw_execute_evidence_task每次最多调用一个已有只读CAD工具，重放原计划与receipt，自动验证文档/实例上下文，独占保存原始返回及新执行记录。CLI可串行跑完整计划，不把整轮COM读取塞入一个MCP请求。
- 文档/位姿变化或超时停止后续调用；普通单项读取失败保留原始错误，其他独立任务和后置检查可继续。必须完整执行且所有guard通过，完整capture才可回填；partial和失败留作诊断。
- cad_reintegrate_evidence沿用原inventory、公差、模板、分组与搜索预算，回填兼容的圆柱、根配合、距离来源，再重算chain/target/rigid/joints/check。旧文件保留；失败不声称部分步骤已形成新结论。
- cad_compare_draft_checks分别报告新出现、仍存在、本次未再观察到及内容变化，附参数/覆盖范围和具体候选。条目消失不证明物理问题解决。
- 三个独立skill，短入口和按需references；算法、文件边界、COM适配继续分开。没有新增CAD修改操作。

## 当前边界

执行器只消费已有计划；原计划的延期任务与未返回发现不自动执行。没有盲目重试、自动扩预算或循环扫描。文件哈希与前后位姿校验不证明几何原子快照，应保持装配不变。

回填需要已有兼容关系/复核基础和明确阈值。单实例约束是补充上下文，面目录不自动确定配对面和测点；这些来源保存在回填报告，但当前规划器还未消费补充清单，不能因此反复采相同数据。已有精确配合面绑定在圆柱来源改变后可能需要独立重采。

开发环境未连接用户SolidWorks；离线逻辑、真实MCP协议和显式替身调用不代表该升降机已完成真实拆解。整机自动划链、自由度/行程/运动/干涉和拆卸路径尚未实现。

## 下一步

1. 扩展新观测复用和约束/面证据关联，让已补采的上下文能参与后续判断；为再次规划增加明确停止条件，避免无效重复扫描。
2. 在用户本机跑通一条真实升降链：从完整空间清单到证据、候选、补采回填和比较，保存真实耗时、错误与原始返回。
3. 在单链结果稳定后，再扩展整机机构链划分、跨链一致性、运动与干涉、行程耦合及拆卸路径。

本机按[0.17.0验收](MCP_ACCEPTANCE.md#0170只读补采执行证据回填与比较)操作，缺少输入交接对应独立能力，不要求人工填映射或确认机械关系。
