# 当前进度与下一步

当前MCP 0.20.0，45个工具、38个功能skill。Windows + 用户已有Conda；原始STEP保持不变。不设置人工复核，未确定信息在结论说明风险。

## 本轮完成：面测量进入草案更新

- 本轮完整且guard通过的面探测可回填已有复核，保留旧观测和原阈值；尚未覆盖的组件对可提供明确复核文件作为依据，只导入当前guarded probe。
- 重算面复核、链清单、目标图、刚体候选、关节草案与检查，模板、实例范围和预算保持原设置。冲突阈值、同面另一快照、容量和缺依据有明确去向。
- 前后比较新增逐组件对的面观测差异，测量变化与来源重写分开，保留阈值覆盖、支持与冲突。新check建索引后续轮，不重复已尝试面。
- 优化一次只读来源重放中的重复文件读取，结束前重新核对路径和哈希；没有新增COM接口、CAD修改操作或工具数量。
- 规划、采集、解释、回填、比较、索引各自独立；详细字段只在需要时加载。

## 当前边界

已接通“读取模型→机构/刚体候选→关节草案→检查→补采具体面→更新草案→防重复续轮”。局部间隙、共面/同轴和模板相似仍是候选证据，不确认真实连接、自由度或运动可行性。小局部间隙不区分接触/穿透/包含，大局部间隙不证明整面分离；零件定义不含装配级切除。

每次回填只消费当前receipt，必须在续轮前处理并用当前有效check更新索引。输入文档、配置、实例身份与位姿必须一致；未测面、竞争解释、截断和原草案风险继续保留。所有停止都只是结束有界采集。

开发环境没有连接用户SolidWorks。合成CAD、真实MCP协议与Windows CI分别记录；该升降机仍待本机完整输出。

## 下一步

1. 对每条候选关节整合配合状态、目标轴线、具体面和参考结构，形成可追溯的支持/冲突解释；区分已有机械依据、仅几何候选和缺失证据，不凭单一近接触合并刚体。
2. 将这套流程用于本机真实单条升降链，保留所有来源、替代解释与未知参数，核对调用耗时和结果完整性；没有实机来源时不虚构拆解进度。
3. 在局部链证据稳定后扩展整机划链、跨链一致性，再开发运动与拆卸路径验证。

本机入口：[0.20.0验收](MCP_ACCEPTANCE.md#0200面证据回填与变化比较)。缺输入交接对应独立能力，不要求人工填面映射或机械确认。
