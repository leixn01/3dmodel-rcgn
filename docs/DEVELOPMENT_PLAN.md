# 当前进度与下一步

当前MCP 0.15.0，38个工具、31个功能skill。Windows + 用户已有Conda；原始STEP保持不变。不设置人工复核，无法确定的信息在结论说明风险。

## 本轮完成：刚体候选与关节草案

- cad_build_rigid_candidates重放目标实例图，生成不合并基线、有效lock配合连通组、单lock对和单接触桥替代方案。每个实例在每个方案中恰归属一个组；保留证据、冲突、范围及省略方案。近接触仅提供弱候选。
- cad_draft_joints在每个保留方案下分别匹配参考窗口。一个参考刚体可对应多个目标零件；输出两端成员、模板类型/自由度假设、目标圆柱的方向/无限轴线候选、未知参数与后续采集建议。
- 两个独立skill按原始JSON交接，算法在cadkin/rigid，文件重放在tools/rigid，复用既有模板搜索。没有新增COM动作。
- 共享搜索预算、同分解释、候选截断和窗口范围全部显式。模板参数不直接迁移；不会凭匹配分数自动判定哪个分组真实。

## 当前边界

分组是条件假设，不是求解器确认的刚体。lock只读取根配合已知状态；接触可能来自滑动、转动、穿透或局部采样。只枚举有界分组策略，没有穷举全部划分。轴线规范点不是枢轴，行程/零位/螺距未知。工具提供补采建议，不在内部启动CAD或执行补采。

自动验收使用显式测试替身和固定参考资产。开发环境未连接用户SolidWorks，尚无本升降机真实分组/关节草案，也没有独立识别准确率。

## 下一步：自动补证据与草案一致性检查

1. 将草案的未知、竞争解释、来源冲突转成可执行的只读补采任务清单；复用现有配合、圆柱、距离、具体面工具，不把采集逻辑放进skill。
2. Agent按任务清单补采后重算依赖，比较前后分组/关节候选，记录哪些差异被解决、哪些仍未知；没有可用信息时保留风险并继续独立部分。
3. 增加整条链的重复归属、相互矛盾轴线/约束、边界联系与跨重复链一致性检查；先形成一条真实升降链可追溯结果，再扩展。
4. 后续再实现局部运动、行程/耦合、干涉与拆卸路径验证。本轮不移动零件、不修改配合、不保存覆盖CAD。
