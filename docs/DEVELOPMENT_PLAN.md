# 下一步：读取组件空间信息

当前为 MCP 0.2.0：13 个工具、8 个功能 skill，已有测试 STEP。用户已确认打开模型可用；其余功能尚待实机验证。具体使用见 [README](../README.md)，工具参数见 [接口约定](TOOL_CONTRACTS.md)。

## 先完成最小联调

在用户安装 SolidWorks 的 Windows 电脑，按 [验收清单](MCP_ACCEPTANCE.md) 优先确认：隐藏/恢复基准面、读取组件树、选择和隐藏/恢复一个组件。记录实际导入类型、软件版本和原始返回；若 STEP 导入为多实体零件，先明确是否能保留装配层级，不能把实体当作组件。其他工具继续按清单补验，不重复宣称全部通过。

## 下一个开发交付

增加只读的**组件空间信息提取**，让 Agent 知道每个零件在哪里、多大：

1. 保留完整实例路径、父子层级、文件与配置；同文件的不同实例分别记录。
2. 读取实例变换，明确局部/整机坐标系、矩阵约定与单位；用子装配和重复实例核对变换组合。
3. 读取包围盒和尺寸，注明坐标系、精度及是否为近似边界；缺失、抑制或轻化数据明确标记，不填零冒充成功。
4. 通过 MCP/CLI 输出可追溯的 JSON，结果保存到 `outputs/`；流程说明独立于执行代码。

验收目标：选至少三个实例（覆盖子装配或重复实例），与 SolidWorks 中的位置和尺寸核对；错误与部分结果不丢失，输入模型不被修改。

## 随后做什么

基于这份结构化清单，先选一条升降链，人工确认固定基体和移动平台，再生成分组及运动关系候选。名称和空间邻近只作为线索；配合、轴线、导程、行程没有证据时保持未知。完整设计保留在 [路线图](ROADMAP.md) 和 [数据契约草案](DATA_CONTRACT.md)。

本轮只清理仓库与明确计划，不提前实现空间提取或自动运动推断。
